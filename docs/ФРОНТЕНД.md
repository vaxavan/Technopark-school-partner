# Переход на отдельный фронтенд (React)

Сейчас интерфейс сделан на шаблонах Django. Сервер при этом устроен так, чтобы отдельный клиент можно было
подключить **без изменений в бэкенде**:

1. **Логика не живёт в представлениях.** Шаблонные страницы и REST API вызывают одни и те же сценарии
   (`materials/services.py`, `submissions/services.py`, `publishing/services.py`, модуль `partners`) и одни и те же
   запросы для экранов (`web/selectors.py`). Правила (роли, конечный автомат, основание утверждения) проверяются
   в сценариях, поэтому обойти их из клиента нельзя.
2. **API покрывает всё, что умеет интерфейс**, включая публичную форму, вход, настройки и отчёт.
   Это проверяет тест `tests/test_api_only.py`: он проходит весь процесс только через API, с включённой
   проверкой CSRF, как настоящий отдельный клиент.
3. **Схема OpenAPI** генерируется автоматически (`/api/schema/`, документация — `/api/docs/`). Из неё
   генерируются типы TypeScript, поэтому клиент и сервер не расходятся.

## Соответствие экранов и API

| Экран (шаблон) | API |
|---|---|
| Форма заявки `/f/<код>/` | `GET /api/v1/public/<код>/`, `POST /api/v1/public/<код>/submissions/` (multipart, `photos`, `form_token` — UUID формы: повторная отправка вернёт ту же заявку) |
| Уточняющие вопросы | `GET`/`POST /api/v1/public/<код>/submissions/<id>/questions/` (`answers`, `round` или `skip`). Ответ содержит `state`: `thinking` — модель думает (показать экран ожидания и повторить GET через 1–2 с), `questions`, `done` |
| Дополнение заявки автором | `POST /api/v1/public/<код>/submissions/<id>/add/` |
| Страница школы по ссылке из письма | `GET`/`POST /api/v1/public/school-link/<токен>/` (`url` или `unsubscribe`) |
| Вход / выход | `GET /api/v1/auth/csrf/`, `POST /api/v1/auth/login/` (`email`, `password`), `POST /api/v1/auth/logout/` |
| Кто вошёл, смена организации | `GET`/`POST /api/v1/auth/me/` (`organization`) |
| Рабочий стол | `GET /api/v1/dashboard/` |
| Заявки | `GET /api/v1/submissions/?status=&q=`, `POST …/<id>/accept/`, `…/reject/`, `…/request-info/` |
| Материал | `GET /api/v1/materials/<id>/`, `…/history/`, `POST …/edit/` (`text` или `command`), `…/restore/`, `…/channels/`, `…/approve/`, `…/reject/`, `…/regenerate/`, `…/unschedule/`, `…/retry/`, `…/mark-published/`, `…/dispatch/`, `GET …/placements/` |
| Расписание | `GET /api/v1/publications/?from=&to=` |
| Справочник школ | `GET/POST/PUT/DELETE /api/v1/schools/`, `POST …/import/` (xlsx), `POST …/<id>/check/`, `GET …/<id>/found/` |
| Отчёт по школам | `GET /api/v1/placements/?material=&status=`, `…/summary/`, `…/export/` (xlsx), `POST …/crawl/`, `POST …/<id>/resolve/` |
| Журнал | `GET /api/v1/events/` |
| Настройки | `GET`/`PATCH /api/v1/settings/`, `PUT /api/v1/settings/platforms/<vk|telegram|max>/` |

Публичные страницы новостей (`/n/…`), RSS для Дзена (`/rss/…`) и служебная админка остаются на сервере:
это не интерфейс приложения.

## Как подключать React, не ломая работающую систему

Переходить можно по одному экрану: старые страницы продолжают работать, пока новые не готовы.

1. **Клиент в той же папке репозитория:** `frontend/` (Vite + React + TypeScript).
   ```bash
   npm create vite@latest frontend -- --template react-ts
   npx openapi-typescript http://localhost:8000/api/schema/ -o frontend/src/api/schema.d.ts
   ```
2. **Тот же адрес, без CORS.** Собранный клиент отдаёт nginx по пути `/ui/`, API остаётся на `/api/`.
   Сессия и CSRF работают как есть: cookie общие, потому что адрес один. В `docker/nginx.conf`:
   ```nginx
   location /ui/ {
       alias /frontend/dist/;
       try_files $uri $uri/ /ui/index.html;
   }
   ```
   При разработке Vite проксирует `/api` на `http://localhost:8000` (`server.proxy` в `vite.config.ts`).
3. **Запросы.** Перед первым изменяющим запросом — `GET /api/v1/auth/csrf/`. Затем значение cookie `csrftoken`
   передаётся в заголовке `X-CSRFToken`, с `credentials: "include"`.
4. **Порядок экранов.** Сначала публичная форма: она самая простая и не требует входа. Затем рабочий стол
   и материал, где отдельный клиент даёт больше всего (три колонки, правка без перезагрузки, опрос состояния
   подготовки текстов). Последними — справочник, отчёт и настройки.
5. **Переключение.** Когда экран на React готов, ссылка в меню ведёт на `/ui/...`. Когда готовы все, корневой
   адрес перенаправляется на `/ui/`, а шаблоны `web/templates/staff` удаляются. Сервер при этом не меняется.

Новая функция сначала добавляется в сценарий (`services`), затем в API, затем в интерфейс. Тогда
`test_api_only.py` продолжает гарантировать, что клиенту хватает API.
