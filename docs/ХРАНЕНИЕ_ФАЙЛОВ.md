# Где хранятся фото, снимки и копии страниц

В базе данных (PostgreSQL) хранятся записи: заявки, материалы, публикации, школы, результаты поиска.
Сами файлы в базе не лежат — в записи хранится только путь к файлу. Файлы лежат в папке `media`:

| Что | Путь внутри `media` | Откуда |
|---|---|---|
| Фото из заявок | `submissions/<номер заявки (UUID)>/<имя файла>` | автор загрузил в форме |
| Снимки и копии наших публикаций и размещений у школ | `evidence/<код организации>/<год>/<месяц>/...png`, `.html` | система после публикации и после подтверждения у школы |
| Снимки и копии страниц из поиска по теме | `searches/<код организации>/<номер поиска>/<номер школы>/<дата>-<n>.png` (`.jpg` от агента), `.html` | поиск по сайтам школ |

Как это устроено на сервере:

- `media` — том Docker `technopark_media`. Он переживает перезапуск и обновление системы.
  Контейнеры `web` и `worker` пишут в него (`/app/media`), `nginx` только читает и отдаёт файлы по
  адресам `/media/...` — по ним работают ссылки «снимок», «копия страницы» и фото в карточке заявки.
- Снимок — изображение всей страницы (Playwright, браузер Chromium в контейнере `worker`). Копия —
  HTML страницы на момент проверки; её SHA-256 записана в базе и в Excel, поэтому подмену копии
  можно обнаружить.
- Фото — до 10 штук по 15 МБ в заявке; снимок страницы обычно 0,3–3 МБ.
- Удаление: «Удалить» на странице поиска удаляет и его снимки. Фото заявок и доказательства
  публикаций не удаляются автоматически.
- Доступ: файлы открываются по прямой ссылке без входа. В адресах фото — длинный случайный номер
  заявки, угадать его нельзя.

Резервные копии:

- `./prod.sh backup` — дамп базы `backups/db-…sql.gz` **и** архив файлов `backups/media-…tar.gz`.
- Восстановить файлы:
  `docker compose -p technopark exec -T web tar xzf - -C /app < backups/media-2026-10-15-1200.tar.gz`.
- Контейнер `backup` (вариант с доменом) копирует ежедневно только базу. Файлы копируйте командой
  `./prod.sh backup` или по расписанию (cron на сервере).
